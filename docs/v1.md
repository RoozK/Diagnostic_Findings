# V1 plan

## Napkin version (prove the idea works)

One web page on localhost. Nothing else.

1. **Record** — capture mic audio in the browser.
2. **Stop** — upload to Deepgram, show the transcript.
3. **Extract** — send the transcript to Claude with `docs/findings-inputs.md` as the reference, show a JSON blob of filled findings.
4. **Copy** — JSON to clipboard.

No database, no login, no patient context, no Berry integration, no styling. API keys in `.env`. Mock patients only.

If the speak → text → JSON loop doesn't work well, nothing else matters.

## V1 (first version worth using in a real consult)

Napkin version, plus:

5. Render findings as a **read-only form view** mirroring Berry's sections (General, Skeletal, Dental, Perio, Soft Tissue, TMJ, Sleep, Habits) — easier to scan than JSON.
6. Every field is **editable** to fix LLM mistakes before copying.
7. **Copy as text** (clinician-readable block to paste into Berry) in addition to JSON.

Still single page, localhost, no auth, no database, no patient identity, mock patients only.

## Deferred (only if V1 proves useful)

Live streaming preview · patient name/DOB · DB & history · AWS/Bedrock/RDS/S3/BAAs · blurb generator · letters · Berry API or browser automation · multi-user/auth/audit · tooth-notation normalization · dropdown-enum harvesting.
